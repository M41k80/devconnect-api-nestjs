DevConnect
API Docs

A production-grade REST API built with NestJS for connecting developers to collaborate on real-world open source projects.

NestJS 11
TypeScript 5
PostgreSQL 14
TypeORM
JWT Auth
Docker
Swagger
✦

Features

🔐
JWT Authentication
Stateless access tokens (30min) + HttpOnly refresh tokens (7 days) with rotation and blacklisting on logout.
🛡️
Role-Based Access Control
USER and ADMIN roles with NestJS Guards protecting sensitive routes and admin operations.
🚀
Project Management
Full project lifecycle from idea to launch, with application system, member management, and soft-delete archiving.
🔍
Project Discovery
Skill-based intelligent matching that scores projects by relevance to the user's tech stack and professional role.
👥
Social Following
Follow/unfollow developers, view followers and following lists for building a developer community network.
📦
Unified Response Format
Global response interceptor and exception filter for consistent envelope format across all endpoints.
🚦
Rate Limiting
Throttler protection on sensitive endpoints. Login rate-limited to 10 requests/minute per IP.
📖
Swagger UI
Auto-generated interactive OpenAPI 3 documentation available at /api when running the server.

Getting Started

Prerequisites

You need the following installed on your system before getting started:

Node.js ≥ 18
Yarn ≥ 1.22
Docker + Docker Compose
Git

Installation

bash # 1. Clone the repository
git clone https://github.com/your-org/devconnect-api.git
cd devconnect-api

# 2. Install dependencies
yarn install

Start the Database

bash # Start PostgreSQL in Docker
docker-compose up -d

# Run migrations
yarn migration:run

Run the API

bash # Development (watch mode)
yarn start:dev

# Production
yarn build && yarn start:prod

🌐 API available at http://localhost:3000/api
📖 Swagger UI at http://localhost:3000/api

Authentication Flow

Access Token
HttpOnly Cookie
TTL: 30 minutes
Refresh Token
HttpOnly Cookie
TTL: 7 days · Rotated on use
Blacklist
Database
Revoked on logout
1
POST /api/auth/login
Client sends email + password. API validates credentials with bcrypt, then issues an access token (30min) and a refresh token (7d), both set as HttpOnly cookies.
2
Authenticated Request
The access token cookie is automatically sent with every request. The JwtAuthGuard validates it using the JwtStrategy and checks if it's blacklisted before granting access.
3
POST /api/auth/refresh
When the access token expires, the client calls /refresh. The refresh token is verified, the old one is revoked in the database, and new tokens are issued (rotation).
4
POST /api/auth/logout
The current access token is stored in the blacklist table. All refresh tokens for the user are revoked. Both cookies are cleared.

Security

🍪 HttpOnly Cookies
All JWT tokens are stored in HttpOnly cookies, preventing XSS-based token theft. Cookies use SameSite: lax and secure: true in production.
🔄 Token Rotation
Each refresh token usage invalidates the previous token and issues a new one, limiting the exposure window if a token is stolen.
🚫 Token Blacklisting
On logout, the current access token is inserted into a blacklist table and checked on every authenticated request until it naturally expires.
🔒 bcrypt Hashing
All passwords are hashed with bcrypt (10 salt rounds). Refresh tokens are also hashed before storing in the database.
🚦 Rate Limiting
Login endpoint is throttled to 10 requests per minute per IP using @nestjs/throttler to prevent brute-force attacks.
✅ Input Validation
Global ValidationPipe with whitelist: true and forbidNonWhitelisted: true strips unknown properties and rejects invalid payloads.
